# Radial reduction ownership decision

Bounded production corpus: 699 Python modules comprising the complete OpenHCS package and setup.py, common revision 32d070c26, with the proposed intensity-distribution module. NRA revision 0844525ecaba93e090a064a4ae4914466b2dae60. Original and final censuses both retain 5,075 original ClassDef rows, 5,063 projected declarations and 12 OPEN/unprojected rows. No new class or family authority is introduced. This is a class census and traced source decision, not an all-detector audit or a semantic proof.

The production question is which existing radial backend performs NumPy measurements, and which owner normalizes its scalar and batched reductions. The existing RadialDistributionBackendStrategy family declares discovery, default selection, common geometry and compiler preparation. Its native leaf remains the independently executable numerical reference and an explicitly selectable provider. Its Numba leaf already declares accelerated scalar and geometry-index consumers.

Before migration, two compiled reducers independently normalize the same histogram, pixel counts and angular-wedge totals. Both allocate intensity fractions in the image dtype, silently truncating integer-image fractions. The batch geometry-index function is also a Python pixel loop despite its Numba name. Selecting it as the default without compiling that loop would regress execution.

Destination ownership:

- The existing request owns aligned/canonical array arguments, geometry projection, and shape/center-cardinality validation. Common parent construction and the accelerated batch both use that request.
- The existing Numba backend owns `arrays_from_bin_totals`, deriving result metadata from the accumulated arrays and invoking one compiled normalization implementation. Its scalar and batch reducers own only their irreducible accumulation algorithms.
- Fractions remain real-valued for integer images. Histogram accumulation and summation preserve the native dtype semantics; centered, two-pass wedge variance and zero-filled undefined coefficients follow the native reference.
- The declared Numba leaf becomes the NumPy default. The family still derives lookup and preparation from its existing declarations; the explicit native provider remains executable. Existing preparation exercises both public consumers for FP32 and FP64 and consequently warms the index, accumulators and shared normalizer. No separate kernel roster, cache wrapper, fallback or registry is added.

Counterevidence and alternatives: putting compiled normalization on the family parent would conflate the independently executed native sparse/masked-array reference with compiled implementation details. Those reference algorithms remain separate intentionally. Removing both compiled normalization copies is stronger than fixing their integer allocations independently. Adding a new result carrier is unnecessary because RadialDistributionArrays already owns the result shape and projection. No compatibility aliases retain the old private reducer names; the global consumer search finds only the migrated consumers in this module.

The three retained NRA recipes source-check the authored transactions and produce projected diffs. That gate establishes exact patch binding and syntax, not mathematical equivalence, live dispatch resolution or performance. Separate tests cover provider selection, preparation, geometry errors, every batched image, integer/floating dtypes, scaled/overflow bins, missing object rows, zero/near-constant/signed/nonfinite images and noncontiguous inputs. Saved production requests and full ordinary-run exports exercise the actual consumer. Fresh spawned interpreters physically load the final FP32/FP64 kernels without writing compiled cache data. Isolated alternating ordinary runs establish execution and total payoff separately from preparation.
