# Worker profiling ownership and admission (#241)

Revision 3032958ac, current perf worktree and shared dependencies; NRA remote main 0844525. The current cProfile receipt mixes server-polling events into execution-thread stacks. Separate wall/thread-CPU saved-frontier replays and GC callbacks reject provenance/GC as dominant costs; profiling correctness is a necessary dependency for the execution goal, not itself evidence of faster ordinary execution.

Existing authorities: WorkerProfilingPolicy owns the optional worker profile boundary; CProfileWorkerProfilingPolicy owns profiler enable/disable/dump and filename projection; OpenHCSProcessEnvironment owns inherited process selectors and import-time policies; openhcs.__init__ invokes those policies before kernel imports. Keep these authorities. Add one nominal monitoring subclass overriding a public event-scoping hook, plus a thread-owned callback value. Common profile lifecycle stays inherited. The standard pre-monitoring runtime leaf remains needed for supported Python 3.11, rather than a legacy application path. Select runtime capability once in existing factory; no extra debug switch, future, service or wrapper registry.

Derive event IDs from sys.monitoring.events and scope all already-registered callbacks, including implied C_RETURN/C_RAISE; get_events alone is insufficient. Do not manually mirror a roster. Call the existing profiler's disable in its common finally block, allowing its existing lease cleanup to release all guarded callbacks, including error paths. NumPy/C/Python/Numba event accounting and no foreign-thread events require independent meaningful tests.

Move the one worker-profile environment literal to OpenHCSProcessEnvironment, and derive Numba monitoring enabled from existing profile-directory activation at package bootstrap before any dispatcher construction. Include these two owned values in existing child-mode projection. Ordinary profile-disabled imports do not enable Numba instrumentation. No internal-import fallbacks, dependency downgrades or silent timing-scope changes. A fresh actual worker profile is required after local concurrent regressions; invalid old mixed-thread profiles remain explicitly rejected rather than substituted into performance claims.
