# Durable native batch evidence (#246)

A fresh 16-well/four-job CP benchmark lost its controller while the original workers remained alive. The old shared bridge held stdout/stderr pipes in memory and wrote logs only after subprocess completion. Original worker reports were rescued by draining their live pipes; all four native analyses and CSV exports completed, but the original controller return code remains unobserved. The recovered timing is explicitly labeled in the new scaling report.

The existing native worker already owns an optional report_path and its final report schema. The one shared _invoke_native_worker bridge now derives this path into the generated request, opens output log files before launch, and reads the worker-owned report after checking its return code. Both matched and synthetic drivers call that bridge unchanged. No extra receipt owner, future, fallback or manual per-driver transport mirror is added. A genuinely standalone worker with no report path still emits its report to stdout; batch file-report workers do not rely on a stdout reader for completion.

19 tests pass. A real child process emits live diagnostics, survives explicit termination of its controller, writes its report and finishes with preserved logs. The bridge consumes its durable report independently of non-JSON stdout. Nonzero exit, missing report and timeout remain failures, each retaining the existing live evidence. Native Python 3.9 physically compiles the worker and barrier sources. The scientific CP pipeline itself is unchanged; this receipt does not claim a new full CP execution of the transport patch.

The global census spans 728 production modules (OpenHCS plus benchmark entrypoints/adapters), 5,232 original classes, 5,220 projected and 12 OPEN, before and after. Original positions and bounded benchmark role excerpts are retained. The public worker request/report declarations are unchanged; the bridge is their consumer, not a new schema authority. The revision-bound NRA authored patch checks source migration, while process tests establish the specific lifecycle behavior. Black and changed source whitespace checks pass; Ruff remains clean for the bridge and tests, with the native 3.9 worker's existing eight diagnostics unchanged. No ordinary execution speedup is claimed; this prevents loss of costly benchmark evidence.
