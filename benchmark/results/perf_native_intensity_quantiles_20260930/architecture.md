# Shared object-intensity sample ownership

Remove generic-partition selection and the duplicated 2-D/dense-3-D/sparse-3-D quantile implementations. The existing NumbaNumpyObjectIntensityBackendStrategy still selects the physical scan representation; ObjectIntensityPixelGroups owns grouped finite samples and projects quartiles/MAD through one native numeric implementation. No provider, fallback, manual preparation roster or second label-domain authority is introduced.

The authorized contracts are CP count*fraction ranks, the existing interpolation order, finite per-object sample membership, image-major measurement ordering, immutable retained samples and the existing 3-D MAD fraction of 1/3. Floating measurements retain CP rtol=atol=1e-6; domain identities, counts and errors remain strict. Production source is cad1c8838, normally merged with current main 642821c3c at 13d055130. All changed production Python is identical across that integration merge.

Before admitting an owner, NRA 0844525e inventoried every original Python ClassDef in openhcs plus setup.py: 699 modules, 5084 original classes, 5072 projected and 12 explicitly OPEN/unprojected. Original scopes/positions and the canonical family projection are retained. Existing alternatives: ObjectIntensityPreparedLabels owns label identity/lookup and prepared foreground positions; ObjectIntensityForegroundIndex owns voxel coordinates/object ordinals; ObjectIntensityArrays and ObjectIntensityFeatureValues own output products/rosters; ObjectIntensityMeasurementRequest owns source/context routing. Radial-bin/display groups and hull/image-series owners have different physical semantics. None owns grouped finite samples shared across all three representations. These are counterevidence to forcing this state onto a richer unrelated owner.

ObjectIntensityPixelGroups is one fixed value/algorithm owner, not a behavior-bearing provider family. Its factories collect the existing physical representations through a shared prefix-buffer primitive; its common projection calls one native selector on a private workspace copy. Existing backend polymorphism remains authoritative. Counts are consumed from the original scan; output shape derives from those counts and group boundaries, not a second object roster. Existing public family preparation exercises these production paths without a separate kernel list.

Native extensions remain declarations in the existing OpenHCSNativeExtension ABC; compilation targets derive from concrete subclasses. IntensityNativeExtension contributes its qualified module name, and the shared parent derives its source path/stable-ABI/compiler policy. OwnedArrayBuffer is moved unchanged from granularity into one common header and consumed by both modules. That C++ relocation is checked by compiler/native-boundary tests and installed consumers, not claimed as a Python NRA proof.

NRA exact-source PatchTargetOperation transactions migrate the production Python declarations and every consumer, with clean syntax/source simulation. Unused sorted helpers and old quantile helper imports are deleted outright. No internal alias or dual reader remains. Source-checked migration, original-class projection, scoped structural ratchet/R1, numerical parity, native buffer safety, saved-input runtime, ordinary end-to-end timings and installed-wheel acceptance are separate evidence gates.

Downselection precedes promotion: two exact Python selectors regress saved-input execution and are rejected; queue flags save only 0.223s across the actual granularity frontier and are deferred. The native prototype removes the largest observed cold dispatcher (5.443s), with an expected small execution ceiling of about0.09s/well. The real production route verifies 0.248s → 0.155s across eight saved inputs, exactly, including the retained-sample copy. Four isolated true-cold preparation observations verify the net whole-preparation gain rather than equating leaf cost with end-to-end benefit.

Persisted formats, registered callables, user pipelines/configuration and third-party contracts are unchanged. Numba caches are derived internal artifacts and recompile from the changed source. Removed internal helper interfaces reset at cutover.

Maintenance experiment: additional image/object groups need only supply the same sample layout and declared measurement shape; all cases use the same quantiles projection. An additional native module belongs to the existing extension family, not a manually synchronized build list. These apply the NRA cookbook derived-view and shared-algorithm principles (examples 1/2). No example justifies an artificial ABC for one fixed sample algorithm. Before/after census, packaged policy receipts and the actual new-extension edit experiment accompany the final report; none proves global physical correctness.
