Source mechanism and ownership
------------------------------

CompiledFunctionGroup.stored_primary_input_edges_for_component selects
stored main-flow edges, then falls back to invocation-domain edges when none
exist. CellProfilerRuntimeAdapterSpec derives the invocation domain from
the module declaration; per-object measurement uses object inputs for cohort
identity. ArtifactPatternGroupExecutionRequest.load_input_stack converts
those stored object values to source-image carriers. That cohort identity
does not prove the carrier contains every measured image input.

RuntimeInputBindingRequest.artifact_value resolves produced image artifacts
through their compiled storage edges. Unstored source aliases instead use
their NamedSourceBinding origin; StepInputSourceUniverseRequest projects
current carrier pixels for primary STEP_INPUT bindings. Consequently a
label-backed carrier can be named as a raw image while still containing
labels. The explicit produced-image witness avoids that particular branch.
This is a source-backed candidate causal mechanism, pending synthetic proof.

Correction belongs to the existing compiled carrier/cohort decision and its
consumers, not a photometry implementation or a second raw-image resolver.
Keep object cohort identity, source binding origin, current transformed
STEP_INPUT pixels, and named produced ImageArtifact identity distinct.
Do not blanket reload raw pixels, add rescale aliases, suppress provenance
checks, or make callers manufacture source metadata. Pattern IDEN-1 applies:
an invocation-domain identity is not proof of the consumed image carrier.
