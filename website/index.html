For imaging scientists and research software teams

Check the whole plate before you run it.

OpenHCS is open-source software for high-content microscopy: studies with many wells, sites, channels, Z planes, or time points that all have to be analysed the same way. It compiles your pipeline against the actual plate first, so a bad setting fails in a second instead of after a night of processing. Then it runs on your CPUs or GPUs.

Source selection, processing steps, and result definitions live in one pipeline. You can edit that pipeline in the desktop app, as Python, import it from a CellProfiler .cppipe file, or hand it to a local agent. All four are looking at the same object.

How it is built

Six rules we hold the code to. They are why the software behaves the way it does, and they are checked, not hoped for.

  1. Check first, then run.

    Every pipeline is compiled against the wells, sites, channels, and planes you selected before any work starts. Missing inputs, wrong types, and settings that cannot work stop the run at the door, not three hours in.

  2. One pipeline, several ways in.

    The GUI, generated Python, and the local agent all edit the same typed pipeline. Build it visually, export the Python, change it in your editor, and open it again. Nothing is translated between formats, so nothing is lost between them.

  3. Say each thing once.

    Each fact lives on the declaration that owns it: a function's contract, a module's settings, an artifact's type. Lists of functions, modules, and clients are derived from those declarations, never copied into a second table that can drift. How ownership works.

  4. Fail loudly.

    An unsupported CellProfiler module stops the import and names itself. Plane labels are never quietly glued across Z. There are no silent fallbacks: if OpenHCS cannot do what you asked, it says so.

  5. Show the receipts.

    Every figure below has a capture and checksum record. The agent run ships uncut, with its transcript, its tool-call log, and the Python it wrote. If we quote a number, you can check it yourself.

  6. Open all the way down.

    MIT licensed. The general parts (configuration, array conversion, storage, process transport, code generation) are separate libraries you can use without OpenHCS. The libraries.

What is in the box

The pieces, what each one does, and the extra to install if it is not in the base package.

Part What it does Install
GUI and Python Build a pipeline visually, export it as Python, edit it, and open it again. Same typed pipeline, function, and artifact model either way. openhcs[gui]
CellProfiler .cppipe import Supported CellProfiler modules become ordinary OpenHCS steps. Unsupported modules fail clearly, by name. API reference. openhcs[cellprofiler-compat]
2D and 3D Dimensionality is function-defined, not a global 2D/3D switch. Volumetric routes include Watershed segmentation, 3D intensity, size and shape, and occupied-volume measurements; plane-local labels are not silently stitched across Z. Capability reference. included
Napari and Fiji Stream images, ROIs, and measurements to Napari or Fiji while the pipeline runs. Each viewer runs in its own process. openhcs[gui,viz]
GPU libraries and custom functions Decorate a plain Python function for CuPy, PyTorch, JAX, TensorFlow, or pyclesperanto. It gets contract checks, a place in the UI, and automatic memory conversion between libraries. openhcs[gpu]
Bio-Formats image I/O Read microscopy formats and their dimension metadata. openhcs[bioformats]
Local MCP Let an agent on your own machine build, check, and run pipelines. See below. openhcs[mcp]

An agent can drive it. Here is the whole run.

The local MCP server gives an agent the same pipeline model the GUI uses. Point it at a microscopy folder or plate and say what you want measured. It can find functions, build the pipeline, compile it, run it, and look at the results. Whatever it builds stays editable in the GUI and as generated Python, so you can check its work.

One prompt, one unattended run

We gave Codex one prompt and a public NeuronCyto II crossover field: two loose TIFF planes. With no further help it mapped the planes to biological channels, built and compiled an editable two-step pipeline in the live desktop app, and ran a per-neuron morphology analysis. It wrote images, ROIs, SWC traces, and measurements, and left a settled Napari result table: 9 neurons and 25 spatial-graph paths.

Then a human looked at the output and found a bug where two neurites cross. We fixed it in the tracing strategy, 0eb5f77c0, and a fresh run gives 9 neurons and 24 spatial-graph paths. The run had also exposed a missing SWC inventory entry, fixed in the format owner, 973c51fd0. That is what the records are for.

Installation

Desktop installers include the GUI and local MCP setup. Use PyPI for headless machines, GPU libraries, or a Python environment you already have.

Desktop installers No Python setup required

Download for WindowsDownload and run — no ZIP to extract Download for macOSOpen the DMG, then open OpenHCS Installer

Per-user, CPU-only installers that include CellProfiler compatibility, local MCP, Napari, Fiji, and Bio-Formats. GPU libraries are optional and not included. Fiji downloads Java on first use. The latest complete GitHub release may trail PyPI. Fair warning: the Windows installer is unsigned and the macOS installer is not notarized, so your OS will ask whether you trust it.
