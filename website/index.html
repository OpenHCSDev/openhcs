One editable bioimage analysis, shared by scientists, code and AI agents.

Open-source analysis for high-content microscopy: plates with many wells, sites, channels, Z planes, or time points. Graphical controls, Python and agents over MCP edit the same pipeline, and CellProfiler .cppipe pipelines import into it. Pipelines run on OpenHCS's own engine: compiled and checked against the selected data, then executed across worker processes on CPUs and GPUs.

Design

  1. Validated before execution.

    The pipeline is compiled against your selected wells, sites, channels, and planes before any work starts.

  2. One pipeline representation.

    The GUI, generated Python, and the MCP server edit the same typed object; there is no conversion between formats.

  3. One declaration per fact.

    Each fact lives on the declaration that owns it; every list is derived from those. How.

  4. Errors, not fallbacks.

    Unsupported input stops with an error naming the cause; nothing is silently substituted.

  5. Published evidence.

    Figures have checksum records; the agent run below is published uncut with its logs.

  6. MIT licensed.

    The general parts are separate libraries.

Processing engine

OpenHCS executes pipelines itself; it does not drive another application. Built from separately published libraries.

Compile, then execute
Before any image is processed, the compiler connects declared inputs and outputs, checks each function's requirements, and plans array conversions and worker assignments. Incompatible settings fail at compile time; workers reuse the plan instead of rebuilding it.
Worker processes
Samples are distributed across worker processes (threads optional). Each worker loads its libraries and GPU context once and reuses them for every sample it is assigned.
Mixed array libraries, CPU and GPU
ArrayBridge converts between NumPy, CuPy, PyTorch, JAX, TensorFlow and pyclesperanto, including CPU–GPU transfers, so steps written for different libraries run in one pipeline without conversion code.
One storage layer
PolyStore reads and writes memory, files, OME-Zarr and OMERO through one interface, and streams results to Napari or Fiji while they are saved. Results keep their source coordinates and producing step.
Separate processes
ZMQRuntime runs the editor, execution server, workers and viewers as separate processes, so editing and inspection stay available while a plate is processing.

Agents (MCP)

The local MCP server exposes the same pipeline model the GUI uses. Pipelines an agent builds remain editable in the GUI and as Python.

Download for WindowsDownload and run — no ZIP to extract Download for macOSOpen the DMG, then open OpenHCS Installer

CPU-only installers that include CellProfiler compatibility, local MCP, Napari, Fiji, and Bio-Formats. GPU libraries are optional and not included. Fiji downloads Java on first use. The latest complete GitHub release may trail PyPI. The Windows installer is unsigned and the macOS installer is not notarized; your OS will ask you to confirm.
